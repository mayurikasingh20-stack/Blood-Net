TECH STACK — Blood-Net (Blood Donation Management System)
Generated: July 31, 2026

OVERVIEW
--------
Blood-Net is a full-stack blood donation management web application with:
- Backend  : Flask (Python) REST API in /Backend
- Frontend : React (Vite) SPA in /frontend
- Database : SQLite (via Flask-SQLAlchemy)

================================================================================
1. BACKEND TECH STACK (Python / Flask)
================================================================================

1.1 Core Framework
------------------
- Flask >=3.1,<4
    The main web framework. Application factory pattern (create_app in
    app/__init__.py), Blueprints for routing, app.config.Config for settings.
    Uses Flask-JWT-Extended for all authentication and authorization.

1.2 Extensions / Libraries (from requirements.txt)
--------------------------------------------------
- Flask-SQLAlchemy >=3.1,<4
    ORM for database models (User, Donor, Patient, BloodBank, Donation,
    BloodRequest, Inventory, InventoryHistory, Camp, Notification,
    ContactMessage, PublicBloodBank, and admin action audit tables).
- Flask-JWT-Extended >=4.7,<5
    JSON Web Token authentication. Issues ACCESS tokens (30 min expiry) and
    REFRESH tokens (30 day expiry). Provides @jwt_required(), get_jwt_identity(),
    custom token error handlers (expired / invalid / missing).
    NOTE: Flask-Login is NOT used. Session-based login was replaced by JWT.
- Flask-Cors >=6,<7
    CORS support so the React frontend (Vite dev server / dist build) can call
    the Flask API cross-origin.
- Flask-Migrate >=4,<5
    Database migrations via Alembic (flask db commands).
- python-dotenv >=1,<2
    Loads environment variables from /Backend/.env (SECRET_KEY, JWT_SECRET_KEY,
    DATABASE_URL, Twilio credentials).
- requests >=2.32,<3
    HTTP client used for external calls, e.g. geocoding (Nominatim/OpenStreetMap
    via geocoding_service.py).
- twilio >=9,<10
    Twilio client used for sending and verifying OTP codes (twilio_service.py:
    send_otp, check_otp) for phone verification and password reset.

1.3 Indirect / Transitive Python Dependencies
---------------------------------------------
- SQLAlchemy >=2.x
    Underlying ORM used directly in services (func, or_, case) for queries.
- Werkzeug (comes with Flask)
    Used directly for password hashing: generate_password_hash /
    check_password_hash (utils/password.py) and secure_filename (file_upload.py).
- Alembic (comes with Flask-Migrate)
    Migration tooling.
- Jinja2 (comes with Flask)
    Template engine dependency (not directly used for rendering since the
    frontend is a React SPA; API returns JSON).
- ItsDangerous (comes with Flask)
    Dependency for Flask signing (used by Flask core).
- Click / MarkupSafe / Blinker / colorama / etc.
    Standard Flask dependency chain.

1.4 Python Standard Library Modules Used
-----------------------------------------
- os, re            : config, env, regex validation (validators.py)
- datetime          : date/time handling for donation cycles, expiry checks
- functools.wraps   : custom decorators (utils/decorator.py role_required)
- random            : OTP generation fallback
- uuid              : generated filenames for uploaded license files
- enum              : model enums (RequestStatus, UrgencyLevel, DonationStatus,
                      InventoryStatus, NotificationStatus, InventoryAction)

1.5 External Services (APIs)
----------------------------
- OpenStreetMap Nominatim
    Geocoding: converts blood bank addresses to lat/lng (geocoding_service.py).
- Twilio Verify
    Sends and validates OTPs for mobile verification / password reset.
- Leaflet/OSM tile layer (frontend side) for map rendering.

4. AUTHENTICATION & SECURITY (IMPORTANT — Flask-Login question)
================================================================================
- FLASK-LOGIN IS NOT USED in this project. The Flask-Login package is neither
  installed nor imported.
- Authentication is handled with Flask-JWT-Extended:
    * POST /api/auth/login  -> returns access + refresh JWT tokens.
    * @jwt_required()       -> protects routes (access token in Authorization:
                              Bearer header).
    * get_jwt_identity()    -> current user id inside protected routes.
    * Refresh tokens with 30-day expiry.
- Passwords: Werkzeug generate_password_hash / check_password_hash (PBKDF2).
- Role-based authorization via custom decorator (utils/decorator.py role_required).
- Frontend stores tokens in localStorage (utils/authStorage.js) and attaches
  them via axios interceptor (services/api.js).
